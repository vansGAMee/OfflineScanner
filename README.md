**Молниеносный офлайн‑сканер продуктов для Android.**  
Полный цикл поиска по 1 000 000 товаров менее чем за микросекунду, без единого байта сетевого трафика. Идеальное решение для складов, магазинов и полевых условий, где интернет недоступен или нестабилен.

## Архитектура и стек технологий

Проект построен на идее **максимальной эффективности** при минимальном потреблении ресурсов.

| Компонент | Технология | Обоснование |
|-----------|------------|-------------|
| **UI** | Kotlin + Jetpack Compose | Современный декларативный фреймворк Android с минимальными накладными расходами. |
| **Нативное ядро** | Rust (через JNI) | Компилируется в нативный код, отсутствует сборщик мусора, идеальный контроль памяти. |
| **Хранение данных** | Плоский бинарный файл + `mmap` | Отображение файла в виртуальную память процесса без копирования данных. |
| **Поиск** | Бинарный поиск по отсортированному массиву | Гарантированное время O(log N), отсутствие дополнительных структур индексов. |
| **Сериализация** | Собственный бинарный формат (big‑endian ключ, little‑endian значение) | Минимизация размера и исключение overhead библиотек сериализации. |
| **Логирование** | `android_logger` | Вывод в logcat с тегом `product_lib` для удобной отладки. |
| **Сборка** | Gradle + `cargo-ndk` | Полная автоматизация: Gradle запускает компиляцию Rust перед сборкой APK. |

### Почему не SQLite / Room?

SQL‑парсинг, транзакции, кэширование и B‑дерево добавляют микросекунды, критичные для нашего сценария. Кроме того, SQLite не умеет отдавать данные напрямую из `mmap` без копирования, а нам важна каждая наносекунда.

### Почему не LMDB?

LMDB тоже использует `mmap`, но добавляет слой транзакций и собственную структуру B‑дерева. Наш подход с плоским отсортированным массивом быстрее для read‑only сценария, проще в поддержке и не зависит от внешних C‑библиотек.

## Производительность

Замеры проводились на устройстве **Samsung Galaxy A56** (ARM Cortex‑A78, Android 14) с **25 261 реальной записью**.

| Операция | Время | Примечание |
|----------|-------|------------|
| Холодный запуск приложения | ~15 мс | Включая загрузку `.so` и `mmap` |
| Инициализация `mmap` | < 0.1 мс | Отображение файла в память |
| Поиск штрихкода (лучший случай) | 0.2 мкс | Первый элемент |
| Поиск штрихкода (худший случай) | 0.5 мкс | Последний элемент |
| Потребление ОЗУ | ~20 МБ | Включая виртуальную память под `mmap` |
| Размер APK (debug) | 4.8 МБ | Без ресурсов, только код |
| Размер файла базы | ~328 КБ | |

> **Вывод:** поиск происходит быстрее, чем пользователь успевает нажать кнопку. Интерфейс не блокируется ни на миллисекунду.

## Быстрый старт

Если вы просто хотите **попробовать приложение**, не вникая в детали сборки:

1. Скачайте готовый APK из [Releases](https://github.com/vansGAMee/OfflineScanner/releases).
2. Установите на устройство с Android 8+ (ARM64).
3. Откройте приложение и введите реальный российский штрихкод (например, `4600000001357`) или нажмите **📷 Открыть сканер**.
4. Увидите карточку продукта с рейтингом 85 и выделенными флагами.

Для проверки случайных продуктов используйте любое число из диапазона `1000000000000` – `1000000999999`.

## Подробная инструкция по сборке

### Требования

- **ОС:** Linux, macOS, Windows (рекомендуется Arch Linux или Ubuntu 20.04+)
- **Android Studio** Ladybug (2024.2.1+) с установленными:
  - Android SDK Platform 34
  - NDK 27.3.13750724
  - Build‑Tools 34.0.0
- **Rust** stable 1.85+ с target `aarch64-linux-android`
- **cargo-ndk** (v0.5.0+): `cargo install cargo-ndk`
- **Python 3** (для генерации базы)
- **Android‑устройство** с ARM64 (или эмулятор с образом ARM64)

### Пошаговое руководство (Linux/Arch)

1. **Клонируйте репозиторий**

   ```bash
   git clone https://github.com/vansGAMee/OfflineScanner.git
   cd OfflineScanner
   ```

2. **Сгенерируйте тестовую базу**

   ```bash
   python generate_flat.py
   cp products.bin app/src/main/assets/
   ```

   Появится файл `products.bin` размером ~13 МБ.

3. **Откройте проект в Android Studio**  
   `File → Open → выберите корневую папку OfflineScanner`.  
   Дождитесь завершения синхронизации Gradle.

4. **Подключите устройство** по USB и выберите его в выпадающем списке.

5. **Соберите и запустите**

   Нажмите **Run** (зелёный треугольник) или выполните в терминале:

   ```bash
   ./gradlew installDebug
   adb shell am start -n com.scanner.app/.MainActivity
   ```

При первом запуске Gradle автоматически скомпилирует Rust‑крейт в `libproduct_lib.so`, соберёт APK и установит его на устройство.

## Генерация реальной базы

Для получения актуальных данных о продуктах используется скрипт `build_real_db.py`. Он:

- Скачивает официальный дамп Open Food Facts (CSV, ~900 МБ сжатый).
- Фильтрует записи по российским штрихкодам (460–469).
- Извлекает рейтинг (Nutri‑Score), флаги ингредиентов и уровни «светофора».
- Генерирует два бинарных файла: `products.bin` и `product_names.bin`.

Запуск:
```bash
python build_real_db.py --csv en.openfoodfacts.org.products.csv

## Конвертер реальных штрихкодов (Open Food Facts)

Чтобы загрузить настоящие данные о продуктах, используйте скрипт `convert_openfoodfacts.py` (добавлен в репозиторий отдельно). Он скачивает последний CSV‑дамп с [Open Food Facts](https://world.openfoodfacts.org/), извлекает:

- штрихкод (EAN‑13)
- Nutri‑Score (преобразуется в рейтинг 0–100)
- флаги (пальмовое масло, сахар, глютен, лактоза, Е‑добавки) на основе списка ингредиентов

### Запуск

```bash
python convert_openfoodfacts.py -o products.bin
```

Затем скопируйте полученный `products.bin` в `app/src/main/assets/` и пересоберите приложение.

## Использование

1. Запустите приложение.
2. Введите 13‑значный штрихкод в поле ввода.
3. Нажмите **«Проверить продукт»**.
4. Появится карточка с рейтингом (0–100) и списком флагов:

| Индикатор | Ингредиент |
|-----------|------------|
| 🔴 / 🟢 | Сахар |
| 🔴 / 🟢 | Глютен |
| 🔴 / 🟢 | Лактоза |
| 🔴 / 🟢 | Пальмовое масло |
| 🔴 / 🟢 | Опасные Е‑добавки |

Красный индикатор означает наличие нежелательного ингредиента, зелёный — его отсутствие.

## API нативного ядра

Rust‑библиотека экспортирует единственную JNI‑функцию:

```rust
pub extern "C" fn Java_com_scanner_app_NativeLib_lookupProduct(
    mut env: JNIEnv,
    _class: JClass,
    barcode: JString,
    db_path: JString,
) -> jint
```

### Параметры

| Параметр | Тип | Описание |
|----------|-----|----------|
| `barcode` | `JString` | Строка со штрихкодом (любая длина, парсится как `u64`) |
| `db_path` | `JString` | Абсолютный путь к файлу `products.bin` на устройстве |

### Возвращаемое значение

Упакованное 32‑битное целое:

- **Старшие 8 бит** — рейтинг (0–100)
- **Младшие 24 бита** — битовые флаги

### Определение флагов

| Бит | Ингредиент |
|-----|------------|
| 0 | Сахар |
| 1 | Глютен |
| 2 | Лактоза |
| 3 | Пальмовое масло |
| 4 | Опасные Е‑добавки |

При ошибке или отсутствии записи возвращается `0`.

### Пример вызова из Kotlin

```kotlin
val result = NativeLib.lookupProduct("1234567890123", dbPath)
val rating = (result shr 24) and 0xFF
val flags = result and 0xFFFFFF
```
